# 原生实时桥接入

[返回首页](../README.md) · [文档导航](README.md) · [画面接口](接口.md)

本页面向需要开发或迁移实时场景的接入者。读取库清单、项目媒体和静态图，不需要安装原生桥。

## 接入需要什么

需要 Windows、已安装的 WE、DSH Desktop 的 Electron 环境，以及能消费桥接口、采集并显示画面的客户端。本仓库目前没有自己的图库或场景属性 UI。

WE 在专用窗口内运行场景，Electron 采集窗口画面，消费方将流作为背景显示。一个 DSH 进程最多维持一个实时场景；隐藏、最小化或停止时应释放窗口和视频流，恢复后重新连接。

## 与底图原生桥共用的入口

本库桥的 IPC 频道使用 `dwl-live:*`，与底图桥的频道分开。但安装器仍沿用 `BGA_NATIVE_BRIDGE_*`、`BGA_NATIVE_PRELOAD_*` 和权限相关标记，preload 也暴露同名的 `window.dshWallpaper`。

**已装底图原生桥时，不要把两套安装当作可直接叠加。** 本安装器会移除并替换匹配标记的已有注入内容，需要同时核对消费方和加载入口的迁移。HTTP 库接口独立，不代表 Electron 原生入口完全独立。

## 安装器做什么

它会改写 DSH 应用目录中的两个文件：

- `resources/app/out/main/index.js`：添加主进程桥加载和定向采集授权入口。
- `resources/app/out/preload/index.cjs`：暴露桥的能力、启停、可见性和属性接口。

这些位置属于 DSH 应用安装目录，不是插件配置目录。安装器要求匹配的桌面代码结构；结构不匹配时会停止。

## 预览、备份与应用

仓库已包含 Windows 辅助程序；需要从源码重建时执行 `npm run native:build`，脚本使用 Windows 的 .NET Framework 编译器。

等任务结束并完全退出 DSH Desktop，再操作安装器。下面目录均为示例，应替换成自己的 DSH 安装位置和一个新的备份目录。

先预览：

```powershell
node tools/install-native-bridge.mjs --app 'D:\Apps\DSH Desktop'
```

预览只报告目标文件和改动摘要。核对后才应用并备份：

```powershell
node tools/install-native-bridge.mjs --app 'D:\Apps\DSH Desktop' --apply --backup 'D:\Backup\dsh-we-bridge-new'
```

备份会保存 `main-index.js`、`preload-index.cjs` 和 `manifest.json`；备份文件必须不存在，避免覆盖旧备份。完成后完全退出并重新打开桌面应用，普通页面刷新无法重载 Electron 主进程。

## 更新与回退

DSH 更新可能覆盖原生入口，需要重新预览并核对是否仍匹配。已安装的桥加载路径指向插件目录，移动或删除目录也需处理原生入口。

回退时先停止消费方的实时背景，再关闭 DSH。应用尚未升级、文件也没有其他后续改动时，可从安装备份恢复两个文件；有后续改动时，应只撤回本安装器的主进程、preload 和权限标记内容，保留其余修改。

## 当前限制

实时场景需要额外运行 WE 并采集画面，资源开销高于静态图。消费方决定采集帧率、超时与静态降级；本仓库没有完整的独立背景客户端，不能仅凭安装桥就保证已显示画面。

鼠标效果依赖壁纸本身的视差或跟随逻辑，不新增原项目没有的交互，也不提供穿透点击或拖动。代码采用窗口采集，不能把进程或端口状态当作动态帧验收。

移植时的权限边界、鼠标对齐和实测记录保留在[原生桥原说明](../we/native/README.md)，其中旧版本号和机器结果属于历史记录。
