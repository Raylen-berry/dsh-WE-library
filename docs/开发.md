## 运行现有检查

需要 Node.js 20 或更高版本。项目没有普通 npm 依赖，也没有安装锁文件；运行以下检查无需先执行 `npm ci`。

不依赖本机 WE 的结构检查：

```powershell
node tools/verify-we-library.mjs
```

完整检查入口包含 6 项语法检查和 3 套检查：

```powershell
node tools/run-all.mjs --list
npm test
```

| 套件 | 核对什么 | 环境要求 |
| --- | --- | --- |
| [verify-we-library.mjs](../tools/verify-we-library.mjs) | 前缀、模块独立性、发现路径与包清单 | 本地源码 |
| [verify-discovery-live.mjs](../tools/verify-discovery-live.mjs) | 实际发现的 WE 目录、项目与库边界 | 本机 WE 与项目；未找到 WE 时会跳过 |
| [verify-live-host.mjs](../tools/verify-live-host.mjs) | 本仓库 `apply()`、独立本机 HTTP 服务与真实请求 | 本机 WE 与库；当前包含必须发现 WE 的断言 |

HTTP 套件执行 `apply()` 时会创建静态图目录。测试前将 `DSH_HOME`、`DSH_WE_LIBRARY_DIR` 指向独立临时目录，避免使用个人数据目录。它从本仓库加载源码，只有显式设置 `DSH_WE_LIBRARY_ENTRY` 才改用另一个入口。

看报告时区分通过、跳过和失败：完整入口通过不代表已经验收原生动态画面。仓库中的旧 README 少列了一套检查，当前清单以 [run-all.mjs](../tools/run-all.mjs) 为准。

## 发布与接入

`npm pack --dry-run --ignore-scripts` 可查看发布包；宿主、`we/`、`tools/`、挂载文件与 `docs/` 都在分发清单中。改接口时对齐 [routes.js](../we/routes.js) 与[画面契约](接口.md)，改包名时对齐 [package.json](../package.json) 和 [cordis.patch.yml](../cordis.patch.yml)。

构建或安装原生桥是单独动作，不属于文档检查或普通测试。安装器会改写应用目录，接入前按[桥](桥.md)核对旧入口、备份和消费方；不要用安装成功代替真实画面验收。
